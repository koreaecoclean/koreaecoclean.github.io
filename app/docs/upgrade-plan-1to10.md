## 2. 현재 앱 구조 (기획서 2장)

### 2-1. 탭과 역할

| 탭 | 누가 보나 | 무엇을 하나 |
| --- | --- | --- |
| **홈** | 전체 | 로고 · 현장 사진 갤러리 · 역할별 입구 버튼 · 회사 홈페이지 배너 |
| **청소 확인** | 고객 | 전화번호(+최초 1회용 코드)로 **자기 업장 방** 입장 → ① 견적 ② 계약 ③ 관리(보고서) |
| **현장 보고** | 팀장 · 직원 · 본부장 | 전화번호+비밀번호+팀장 고유코드(또는 직원 초대코드) → 관리업장 · 계약서 · 근무태도 · (구입자만) 장비·봉투 |
| **관리** | 대표 · 본부장 | 대표: 매출·견적·계약·직원계약·장비영수증·코드·고객계정 전부 / 본부장: 현장·직원 체크만(금액 비노출) |

- 대표 계정은 **관리자 모드 ↔ 직원 모드**를 화면에서 전환합니다(v2.7.0). 직원 모드에서는 대표가 팀장처럼 현장을 골라 보고서를 씁니다.
- 하단 탭은 역할에 따라 숨겨집니다(대표·본부장만 `관리` 탭).

### 2-2. 세 개의 방 (대표가 2026-11-26에 정한 구조)

| 방 | 단계 | 실제 화면 |
| --- | --- | --- |
| 고객 방 | ① 견적 | 견적서(금액·범위·주기·사진·PDF/인쇄) → [이 견적으로 계약 진행] |
| | ② 계약 | 표준 도급 계약서 · 전자서명(전용 서명창) · 사업자등록증 업로드 · 특이사항 |
| | ③ 관리 | 처음부터 지금까지 3단계 비교(첫 견적 오염 → 첫 대청소 → 정기 관리) + 일자별 보고서 + 사진 확대 |
| 직원 방 | 관리업장 | 담당 업장 카드 → 청소공정 매뉴얼(요일별 체크) → 사진 3분류 → 보고 등록 |
| | 계약서 | 내 도급계약서(제1~11조)·별첨본 확인·서명 |
| | 근무태도 | 본부장이 매긴 A~F 등급 이력(본인 것만) |
| | 장비·봉투 | 구입 신청 · 내 영수증(인쇄/PDF) — 구입 당사자만 |
| 관리 방 | 대시보드 | 보고 확인·고객사 제출 / 전체 매출 / 견적·계약 / 직원·계약 / 장비·영수증 / 현장·코드 / 고객 계정 |

## 4. 부분 구현 · 미연결 기능 (원인별)

| # | 증상 | 원인(코드 근거) | 1단계 처리 |
| --- | --- | --- | --- |
| 1 | 견적 → 계약 → 업장이 **이름 매칭**으로만 이어짐 | `signAgreement` 가 `siteId` 없으면 업장 이름으로 찾고, 없으면 새 업장 생성. 견적에 `siteId`가 없으면 계약서도 업장을 모름 | **해결** — `quote.siteId`·`contract.siteId`·`site.quoteId`·`site.contractId` 4방향 연결, 견적이 업장에 붙어 있으면 서명해도 **업장을 새로 만들지 않음** |
| 2 | 보고서가 "어느 계약의 작업인지" 모름 | `reports` 에 `siteId`·`leader` 이름만 저장 | **해결** — `report.contractId`·`staffContractId`·`accountId` 자동 연결 |
| 3 | 업장 ↔ 팀장 계약이 한쪽만 연결 | `staffContracts.siteIds` 만 있고 업장에는 없음 | **해결** — `site.staffContractIds` 유지(배정/해제 시 동기화) |
| 4 | 업장을 등록해도 견적을 다시 입력 | 견적 등록 폼이 빈 칸 | **해결(API)** — `addQuote({siteId})`/`createQuoteForSite()` 가 업장 값 승계. 화면 버튼은 2단계 견적 화면에서 붙임(아래 11장) |
| 5 | 계약·업장 정보를 바꿔도 흔적이 없음 | 이력 저장 없음 | **해결** — 업장/견적/계약/직원계약 안 `history[]` + 화면 표시 |
| 6 | 직원 계약과 계정이 따로 | 계약 등록 시 계정을 고르지 않으면 `accountId` 빈 값 | **해결** — 같은 번호의 팀장 계정 자동 연결, 체결 시 별첨 업장을 계정에 배정 |
| 7 | 고객에게 "예정 일정"이 없음 | 일정 데이터 자체가 없음(보고 날짜만) | **미해결(6단계)** — 이력·연결만 준비 |
| 8 | 팀장 계약 별첨이 담당 밖 계약에서 조용히 빠짐 | `syncStaffContractSites` 가 미체결 계약에서 업장을 제거 | **위험 기록** — 고객 계약 서명 시에는 제거하지 않도록 수정(`{remove:false}`). 관리자가 담당 팀장을 바꿀 때의 제거는 기존 의도 유지 |

## 5. 중복 기능 (정리 결과)

| 중복 | 위치 | 처리 |
| --- | --- | --- |
| 현장 정보 입력 | 새 현장 등록 폼 · 업장 "계약·운영 정보 관리" 폼 | 중복 아님 — 등록은 최초 1회, 이후 한 폼에서만 수정(그대로 유지) |
| 청소 점검 항목 | `site.checklist`(업종 기본) · `site.manual.days[].areas[].items`(요일 매뉴얼) | 매뉴얼이 있으면 매뉴얼, 없으면 체크리스트 — 한 화면에서 하나만 사용(유지) |
| 고객/팀장/대표 로그인 폼 | 세 화면에 각각 | 의도된 분리(입구가 다름) — 그대로 |


- `site.quoteId` — 이 업장이 나온 견적

- `history[]` — `{id, at, actor, action, note, changes[{field, from, to}]}` (레코드당 최근 200건)

## 9. 1단계에서 실제로 구현한 것 (v2.7.1)

### 9-1. 데이터 계층 (`js/store.js`, `js/seed.js`)

1. **연결 필드 정규화** — `normalizeSite/Quote/Agreement/StaffContract/Report` 가 위 연결 필드와 `history` 를 항상 같은 모양으로 돌려줍니다(없는 예전 레코드도 안전).
2. **이력 도우미** — `recordHistory()` · `listSiteHistory()` · `diffFields()` · `normalizeHistory()`(중복 id 제거, 200건 제한).
3. **업장 연결 조회** — `siteLinks(siteId)`(견적·계약·팀장계약·보고·고객·이력 한 번에), `listSiteLinks()`(관리 화면 카드용 전체 요약).
4. **연결 자동화**
   - `addQuote({siteId})` / `createQuoteForSite(siteId, {amount})` — 업장의 고객사·주소·담당자·사업자번호·세금계산서·주기·면적·청소공정을 그대로 승계(빈 칸만).
   - `createAgreementFromQuote()` — 견적의 `siteId`(없으면 상호명 일치)로 **기존 업장에 연결**, 견적에 `contractId` 기록, 업장에 `quoteId/contractId` 채움, 이력 기록.
   - `signAgreement()` — 새 업장을 만들 때 처음부터 `quoteId/contractId` 를 넣고, 기존 업장이면 **재사용**(중복 업장 방지). 서명·금액·계약일·청소공정 승계는 기존과 동일. 업장 이력에 "고객 계약 체결".
   - `updateSite()` / `updateSiteDetails()` — 계약금·도급금액·수수료·계약일·청구일·청소공정·출입·주차·담당 팀장 등 **바뀐 칸만** 전/후 값과 함께 이력에 기록.
   - `syncStaffContractSites()` — 업장↔팀장 계약을 양쪽에서 유지하고 이력 기록. 고객 계약 서명 시에는 **add-only**(기존 별첨을 빼지 않음).
   - `addStaffContract()` — 계정을 고르지 않아도 **같은 번호의 팀장 계정 자동 연결**, 업장에 `staffContractIds` 추가, 등록 이력.
   - `signStaffContract()` — 서명한 팀장 계정에 별첨 업장 배정, 업장에 계약 id 연결, 이력.
   - `addReport()` — `contractId/staffContractId/accountId` 자동 연결 + 업장 이력 "청소 보고 등록". `approveReport()` → "고객사 제출". `deleteReport()` → "보고 삭제".
5. **마이그레이션 `_migrateSiteLinks()`** (SEED_VERSION 11 → **12**, 부팅 때 자동)
   - 원칙: **비어 있는 칸만 채움**. 기존 금액·날짜·서명·보고·코드는 다시 쓰지 않음. 여러 번 실행해도 결과 동일(멱등).
   - 채우는 것: 계약→업장/견적, 업장→계약/견적/팀장계약, 보고→계약/팀장계약/계정, 직원계약→계정(전화번호 일치).
   - 결과: 라이브 데이터 63행에서 **기존 필드 164개 전부 보존**, 연결만 추가(테스트로 확인).

### 9-B-2. 계산 규칙 (임의 확정 금지)

- 기준표: 기획서 7장 21줄 그대로. `PRICE_TABLE` 상수이며 관리자만 수정 가능(수정 시 전/후 값 이력).
- 표에 없는 평수: `areaRule.mode` 가 `perPyeong`(1평당 최소·최대) 또는 `interpolate`(양옆 기준표 사이 비율)일 때만 계산. 없으면 `base=null`, 최종 금액 없음, 경고 문구.
- 권장 견적: 표의 최소/중간/최대 중 선택(기본 `mid` = (최소+최대)·½).
- 조정: 1·2·3·4인팀 / 주 1·2·3·5회·매일 / 난이도 4단계 / 추가 공정 6종 / 작업시간 / 기타 조건 — 각 항목 `{mode:'', 'rate', 'amount', value}` 이고 **기본값은 빈 값(미설정)**. 비어 있으면 계산에서 빠지고 `미설정` 배지 + 경고로 표시.
- 최종 = 권장 + 조정 합계. 신청자가 ‘최종 견적 직접 입력’을 채우면 그 금액을 사용(견적 카드에 ‘직접 입력’ 표시).
- 승인 뒤 금액을 바꾸면 `approval` 이 자동 해제되어 다시 승인을 받습니다.

### 9-B-3. 화면

- 관리(대표) → **「현장 방문 · 자동 견적」**: 기존 업장 불러오기(1단계 `createQuoteForSite` 연결) · 방문 등록 폼 · 터치형 구역 체크리스트 · 입력 중 실시간 자동 산출 상자 · 구역별 사진 등록/이력 · 금액 승인 대기 목록.
- 관리(대표) → **「견적 기준표 · 체크리스트 설정」**: 기준표 21줄 편집 · 표 밖 평수 규칙 · 권장 기준 · 조정 항목(미설정 시작) · 체크리스트 구역/항목 추가·수정·삭제 · 최근 설정 변경 이력.
- 견적 카드: 자동 산출 요약(기준/권장/조정/최종) · 승인 상태 · **[견적 수정]** · **[금액 승인]**.

- 부관리자(본부장) 화면에는 이 패널·기준표·금액 승인이 나오지 않습니다(기존 권한 분리 유지).

### 9-B-4. 연결

- 저장: 새 고객이면 **업장 1곳 + 견적 1건**, 기존 업장이면 그 업장에 견적만. 업장 `quoteId`·`contractId` 유지.
- 승인 → `createAgreementFromQuote()` 로 계약서 자동 생성(같은 견적의 계약서를 두 번 만들지 않음, 업장 중복 없음).
- 계약 체결 시 견적의 방문 기록이 비어 있는 업장에 옮겨집니다(기존 업장 기록은 덮지 않음).
- 대표 견적을 수정하면 그 업장의 방문 기록도 같은 값으로 맞춰 업장 카드와 견적이 어긋나지 않게 했습니다(이력 기록).

- 상태(`ASSIGN_STATUS`): `pending` 배정 제안 중 · `accepted` 수락 완료 · `rejected` 거절됨 · `canceled` 철회됨 · `superseded` 새 요청으로 대체.
- 출입 방식(`HANDOVER_ACCESS_TYPES`): 공동현관 번호 · 출입카드 · 출입문 비밀번호 · 열쇠 · 지문(방식만) · 경비실 호출 · 상주 직원 · 기타.

### 9-E-2. 저장소 함수

- `saveSiteHandover(siteId, patch)` — 대표만. 바뀐 칸 diff → `handoverHistory` + 업장 이력, `ops`(출입·쓰레기·주차)와 `contract.subcontractAmount` 동기화, 지워진 사진 참조 제거.
- `saveSiteSecret(siteId, {doorCode, note})` / `revealSiteSecret(siteId, {actor})` — 일반 정보와 분리, 배정된 팀장만 열람 + `log`·업장 이력.
- `requestSiteAssignment(siteId, {leaderId, amount, payDay, terms, note})` — 인수인계 필수, 관리팀장만(본부장 제외), 수락된 배정·확정된 배정 차단, 같은 팀장 재요청은 갱신, 다른 팀장 요청은 이전 대기분 대체. 보내는 도급 조건을 인수인계 `pay` 에도 반영(버전 +1).
- `cancelSiteAssignment(siteId, id)` — 수락 전 요청만 철회.
- `listAssignmentRequests(session)` — 본인 계정 요청만, 고객 금액·계약서·견적·개인정보 제외한 제한 뷰.
- `acceptSiteAssignment(id)` — 본인만. 도급계약서(`S-연도-번호`, `sent`) 자동 생성 + 업장·계정 연결, 나머지 대기 요청 정리.
- `rejectSiteAssignment(id, {code, reason})` — 본인만, 사유 필수, 사유·일시 기록.
- `signStaffContract()` — 배정에서 온 계약이면 서명 시 `site.manager/managerRole/assignee`, `assignments[].confirmedAt`, 업장 도급금액 정합, 「팀장 배정 확정 · 현장 보고 활성화」 이력.
- `siteForStaff()` — 인수인계(사진 썸네일 포함) · 담당 확정 · `secretSet`(값 아님) · 열람 기록 수만 넘김. `siteForCustomer()` 는 새 필드를 넘기지 않음.

### 9-E-3. 화면

- 관리(대표) → 업장 카드 → **「인수인계 · 팀장 배정 (vN)」**: 인수인계 입력 폼 + 현장 사진 선택 + 항목별 확인 + 도급금액/지급일, **출입 비밀번호 · 보안 메모**(분리), **팀장 배정 요청** 폼과 요청 이력(상태 · 거절 사유 · 계약서 열기 · 철회), 인수인계 이력.
- 현장 보고(팀장) → **「내 배정」** 탭: 수락 대기 카드(인수인계 · 사진 · 도급금액 · 지급일 + [배정 수락] / [거절 + 사유])와 지난 배정(수락 완료 → [확인 · 서명], 거절 사유).
- 현장 보고 → 업장: **인수인계 카드**(버전 · 담당 확정 · 전체 항목 · 사진 · 도급금액/지급일/지급 조건 · 출입 비밀번호 ［보기］).
- 본부장 · 다른 팀장 · 고객 화면에는 인수인계·배정·보안정보가 없습니다.

## 10. 구현 상태 표기 규칙 (기획서 30장 7·8항)

화면에서 "되는 것처럼" 보이지 않게 다음 규칙을 씁니다.

- 새 기능을 붙일 때 **버튼은 실제 저장·조회가 연결된 것만** 노출합니다. 데이터만 있고 화면이 없으면 화면을 만들지 않습니다(예: `createQuoteForSite` 는 API·테스트만 있고 버튼 없음 → 2단계 견적 화면에서 버튼과 함께 공개).
- 외부 설정이 필요한 기능(메일 발송·푸시·GPS)은 **"설정 필요"** 배지를 붙이고 켜지 않은 상태로 둡니다.

## 12. 데이터 보호 원칙 (라이브 운영 데이터)

1. 마이그레이션은 **추가만** 합니다. 값 변경·삭제는 사용자가 화면에서 하는 동작으로만.
2. `SEED_VERSION` 을 올려도 **기존 레코드를 시드로 덮어쓰지 않습니다**(`_ensureSeed*` 는 없는 것만 추가).
3. 새 필드는 항상 "비어 있으면 채운다"로 처리하고, 이미 값이 있으면 손대지 않습니다.
4. 테스트는 ① 실제 운영 스냅샷 사본으로 마이그레이션을 돌려 필드 보존을 비교하고 ② 브라우저 테스트는 `localhost`(동기화 자동 꺼짐)에서만 돕니다.
5. 라이브 DB에 테스트 데이터를 넣지 않습니다. 불가피하면 즉시 삭제하고 삭제 전/후 행 수를 기록합니다.
